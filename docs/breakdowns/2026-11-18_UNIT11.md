- File nghe không cần Speech API. Nghe chậm ở 0.8 lần; không tự phát, dừng khi đổi nhóm/giọng hoặc ẩn/rời trang; lỗi tải có thể bấm nghe lại.
- Giữ chung một HTML Audio element qua chuỗi đánh vần để phù hợp quyền phát theo phần tử trên iPad. Cần người dùng thử thực tế, không coi giả lập là iPad thật.
- Có thể chọn giọng thiết bị nếu có. Unit cũ tiếp tục dùng giọng thiết bị; chưa thay hàng loạt tập một trước khi người dùng duyệt mẫu.

## Bài học và điểm chặn tái phạm

1. Giọng đọc ảo là object thường, không gán nó vào setter `SpeechSynthesisUtterance.voice` của trình duyệt. Dùng object lệnh riêng cho recorded; khi chọn giọng thiết bị mới tạo native utterance. QA phải có cả trường hợp còn và mất Speech API.
2. Gọi TTS từng chữ đơn không đảm bảo đọc tên chữ (đặc biệt A); tạo clip alphabet với SpellOut và kiểm đúng thứ tự/highlight, không chỉ kiểm nút bật.
3. Kiểm audio phải tải/giải mã và phát thật. Chromium dùng Web Audio; bản WebKit Windows thiếu API này dùng kiểm PCM16 và metadata media, đồng thời vẫn phải phát clip thật. Ghi rõ khác biệt, không giả lập kết quả phát.
4. Tách runtime khỏi authoring: máy học sinh/CI không cần giọng Zira; WAV là tài nguyên đã tạo. Không cài thêm gói trên máy bé để che lỗi website.
5. Bộ QA speech mô phỏng dùng riêng nhánh giọng thiết bị; runner file nghe thật độc lập kiểm recorded branch. Cả hai phải đạt trước khi mở rộng audio sang Unit khác.

Chưa duyệt phát âm bằng tai, chưa xác nhận trên iPad của bé, chưa đánh giá độ khó với học sinh. Không có thu âm/chấm nói hay đồng bộ tài khoản.

Lưu ý bản file rời: WAV nhúng phát được trên Chromium. WebKit Windows không phát được WAV nhúng khi mở file URL (kể cả thử Blob); kiểm tra WebKit tập trung bản HTTP/Pages và xác nhận đủ dữ liệu nhúng, không báo đã đạt phát offline trên Safari/iPad.

WebKit local đã đạt phát HTTP thật với thao tác cảm ứng/kích thước tablet, đủ 91 WAV hợp lệ/metadata, nghe thường/chậm, ABC, dừng chuỗi/đổi nhóm, HTTP 404/thử lại và ba cấp nghe trong đề. Báo cáo `artifacts/unit11-local-webkit/audio-report.json`. WebKit Windows không chuyển request media qua Playwright routing, nên ca lỗi dùng URL thật trả HTTP 404; Chromium dùng chặn request. Giới hạn file URL giữ như trên.
